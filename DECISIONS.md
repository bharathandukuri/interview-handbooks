# DECISIONS.md

> Tracks every assumption, ambiguity resolution, and deviation from the spec.
> Updated as the build progresses.

## Pre-Build Decisions

| #   | Decision                         | Context                                                    | Choice                                                                                                  | Rationale                                          |
| --- | -------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 1   | `Kbd` component                  | Spec §3 lists `kbd` among shadcn components                | Added via `npx shadcn@latest add kbd` (`src/components/ui/kbd.tsx`)                                     | Verified `kbd` exists in `shadcn@latest` registry  |
| 2   | TanStack Router version          | Spec says `@tanstack/react-router` with file-based routes  | Use latest stable (v1.x) with `@tanstack/router-plugin` for Vite                                        | File-based routing requires the Vite plugin        |
| 3   | Framer Motion import             | Package is now published as `motion` (not `framer-motion`) | Import from `motion` per spec                                                                           | Spec explicitly says `motion`                      |
| 4   | `build:single` on Windows        | `HANDBOOK=python` env var syntax is Unix                   | Use `cross-env HANDBOOK=python` or Vite `--mode single` with `define`                                   | Windows compatibility                              |
| 5   | Font inlining for `build:single` | Spec requires fonts inlined for offline use                | Use Vite `assetsInlineLimit` or manual base64 injection                                                 | Test in M0 to validate approach                    |
| 6   | Route structure for `/#/_kit`    | Dev-only design system page                                | Use a lazy route that is tree-shaken in production via `import.meta.env.DEV` guard                      | Zero production cost                               |
| 7   | Shiki languages                  | Loading all languages bloats the bundle                    | Load only `python`, `javascript`, `typescript`, `bash`, `json`, `yaml` initially; add more per handbook | Stays under 180 KB budget                          |
| 8   | `progress-ring` animation        | Spec says "animated sweep"                                 | Use SVG `stroke-dashoffset` transition with CSS, not JS animation                                       | Simpler, respects `prefers-reduced-motion` via CSS |
| 9   | Card section splitting           | Spec says sections split by H2                             | Split the rendered HTML string at `<h2>` tags, keying by the heading text content                       | Straightforward string processing at build time    |
| 10  | `readTime` auto-estimation       | Spec says "auto-estimated if missing"                      | Count words in body, divide by 200 wpm, round up to nearest minute                                      | Standard reading speed estimate                    |

## During-Build Decisions

| #   | Decision                                    | Context                                                                                                                                     | Choice                                                                                                                                                                                                                          | Rationale                                                                                                            |
| --- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 11  | `--accent` token vs shadcn `--color-accent` | Spec §9 defines `--accent` as handbook brand colour (`#4A90E2`), while shadcn uses `--color-accent` for subtle dropdown/menu hover surfaces | Keep `--accent` / `--accent-2` / `--accent-soft` / `--accent-ring` on `:root`, map `--color-primary` to `var(--accent)`, `--color-brand*` to handbook accent tokens, and `--color-accent` to `--ui-accent` (`var(--surface-2)`) | Preserves calm Linear/Raycast surfaces in shadcn menus while exposing exact Spec §9 tokens and WCAG AA `--accent-fg` |
| 12  | Literal `/_kit` route file name             | TanStack Router treats `_`-prefixed filenames as pathless layout routes                                                                     | Name the route file `src/routes/[_]kit.tsx` and guard rendering behind `import.meta.env.DEV`                                                                                                                                    | Escapes `_` in TanStack Router file routing so the hash URL is `/#/_kit`                                             |
| 13  | Settings store persistence key              | Spec §8 specifies `ihb:v1` for progress; `SettingsState` is separate                                                                        | Persist `useSettingsStore` under `ihb:settings:v1` (version 1 with `migrate`) and replace shadcn's `next-themes` dependency                                                                                                     | Keeps progress (`ihb:v1`) and settings decoupled while removing unused `next-themes`                                 |
| 14  | WCAG AA foreground on `--accent`            | Spec §9 requires text on accent backgrounds to pass WCAG AA                                                                                 | Compute `--accent-fg` dynamically via relative luminance (`#0B0D12` for `#4A90E2` gives 5.45:1; white gives 3.29:1)                                                                                                             | Ensures every handbook accent colour automatically satisfies WCAG AA contrast                                        |
